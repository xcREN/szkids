## 一、怎么跑起来

### 用微信开发者工具打开

有两种打开方式，选一种即可：

| 打开的目录 | 说明 |
|---|---|
| `鹏飞公园活动`（仓库根目录） | 根目录的 `project.config.json` 已指向 `weapp/miniprogram/`，直接能编译 |
| `鹏飞公园活动/weapp` | `weapp/project.config.json` 指向 `miniprogram/`，同样能编译 |

> **之前编译报「在项目目录根目录未找到 app.json」，就是因为这两个配置里缺 `miniprogramRoot`。现在两个都补上了。**
> 如果工具里还报这个错，点「项目 → 重新打开此项目」，或者关掉项目重新打开一次让它重新读配置。

### 定位权限

首页要用定位算距离。模拟器右上角可以模拟位置；真机第一次进会弹授权框。
**拒绝授权也能正常用**，只是距离按深圳市民中心估算，页面底部会写明。

### 用的是模糊定位，不是精确定位

代码里调的是 **`wx.getFuzzyLocation`**，不是 `wx.getLocation`。这不是偷懒，是被卡的：

`wx.getLocation` 要在 mp 后台单独申请开通，微信的开通条件是
「具备与实时地理位置强相关的使用场景」—— 指导航、打车、跑腿这一类。
「推荐附近适合孩子的地方」不符合，后台会直接显示**类目未符合开通条件**，
个人主体基本申请不下来。而且只要 `app.json` 的 `requiredPrivateInfos` 里写了
`getLocation`，**提交审核时会被拦下**，报「接口无权限」，连提交都提交不了。

`getFuzzyLocation` 不用申请，开箱可用，代价是经纬度只到公里级。对这个产品的影响：

| 功能 | 受影响吗 |
|---|---|
| 按距离排序、筛「附近 10km」 | 基本不受影响 |
| 地图上 Marker 的位置 | 完全不受影响（地点坐标是固定的） |
| 天气 | 不受影响（本来就按城市取） |
| 「离你 800m」这种精确说法 | **受影响，已经改掉** |

最后一条的处理方式：`app.js` 会在 location 对象上打一个 `fuzzy` 标记，
`utils/geo.js` 的 `formatDistance` / `formatDriveMinutes` 据此把文案说得含糊些
（`3km内`、`8km左右`、车程取整到 5 分钟），地图页底部也会写明「距离是大致值」。

**宁可说得含糊但可信**：误差本来就有几公里，还显示「离你 800m」，
用户按这个数字决定去不去，到了发现不对，这比不显示更糟。

哪天真申请下来了 `getLocation`，把 `app.js` 顶部的 `PRECISE_LOCATION` 改成 `true`，
`app.json` 的 `requiredPrivateInfos` 换回 `getLocation`，别处不用动。

### 云开发

Phase 1 不依赖云开发。`app.js` 里的 `wx.cloud.init` 做了容错，没开通云环境也不会影响地图。

```

      ▼

      ▼

      │
      ▼

      ▼
```

### 关于「微信登录」这一项

PRD 的 Phase 3 里写了微信登录，这版**故意没做**，理由：

1. 这些数据（孩子、收藏）只服务用户自己，没有跨设备协作需求，本地存储够用；
2. 不强制登录，用户打开就能用，个人主体小程序过审也更稳；
3. 真要上云同步，改动集中在 `utils/store.js` 一层的读写函数里，页面代码一行不用改
   （文件末尾写了具体怎么接：云数据库靠 `_openid` 自动隔离，连登录都不用自己做）。

如果你确实想要跨设备同步（比如爸爸妈妈两台手机共用一份收藏），告诉我，
那一版需要开通云开发环境，我再补。

### 关于统计口径（重要）

- **探索度的分母是「当前收录的地点数」**，收录会越来越多，所以百分比可能会「变小」。
  页面上写清楚了分母（`8/26`），不然用户会以为自己在倒退。
- 所有数字都由打卡记录**实时算出来**，不单独存一份统计结果——
  改了删了打卡，数字立刻跟着变，不会对不上。

## 三之五、Phase 5 做了什么

- [x] **实时天气** —— `utils/weather.js` + `weather.config.js`。
      首页顶栏显示深圳实时天气，点一下会说一句「今天适合去什么样的地方」。
- [x] **今天去哪** —— `pages/today/`。天气 × 年龄 × 兴趣 × 距离 × 新鲜度，**只推 3 个**
      （PRD 十五：帮用户做决定，不是制造更多选择），每个都写明为什么是它。

### 天气接口：默认不需要 key

用的是 [Open-Meteo](https://open-meteo.com/en/docs)，**开源、免注册、不用 key**，
所以 `weather.config.js` 通常一个字都不用改。和风、彩云也都支持，换 `provider` 就行，
字段差异在 `utils/weather.js` 里抹平了，下游代码不用动。

（Open-Meteo 的免费额度面向非商业用途，官方标注每天 1 万次以内。
个人自用差着好几个数量级；真要商用再换和风/彩云或买它的商业套餐。）

**但域名白名单跑不掉**：mp 后台「开发管理 → 开发设置 → 服务器域名 →
request 合法域名」里必须加 `https://api.open-meteo.com`。
免 key ≠ 免白名单，而且开发者工具勾了「不校验合法域名」照样能跑，
很容易到真机上才发现 —— 这是这一环最容易踩的坑。

### 六个天气档是怎么来的

`data/places.js` 里每个地点的 `weatherTags` 只有六个键
（`sunny` / `cloudy` / `lightRain` / `heavyRain` / `hot` / `cold`），
而接口返回的天气现象有几十种。归一在 `utils/weather.js` 的 `classify()` 里做，
判断顺序是**下雨优先于冷热**：34℃ 又在下暴雨时，
决定「今天能不能去户外」的是雨不是热。

冷热用的是**体感温度不是实际温度**。深圳夏天湿度大，实测过一组真实数据：
实际气温 32.0℃、体感 37.4℃ —— 按实际温度会判成「多云」照常推户外，
按体感才判成「高温」推室内和玩水。这个差别足以让推荐结果完全不同。

### 推荐怎么打分

六个维度加权（权重见 `utils/recommend.js` 顶部的 `WEIGHTS`），外加一条硬规则：

**今天这档 `weatherTags` 是 0 分的直接排除**，不参与打分。
0 分在 `places.js` 里的语义就是「这天别去」（比如暴雨天的空旷草地），
让它靠距离近、评分高把分补回来是错的。

另外三个候选之间做了**分类去重**：选中一个之后，同分类的剩余地点打七折再选下一个。
三个都是公园对「今天去哪」这个问题没有帮助 —— 用户要的是三个不同方向。

摇一摇不是纯随机，是在前 8 名里按分数加权抽：
纯随机会抽到暴雨天的沙滩，一次就把信任毁掉；只取第一名又失去了「摇」的意义。

### 验证情况

打分和归一逻辑在 Node 里跑过一轮（26 条真实数据，21 项断言全过），验的是：
暴雨天出的 3 个必然全是室内、高温天不出空旷暴晒型、3 个不会同分类、
打卡过的会掉出第一、摇一摇 200 次从没抽到「这天别去」的地点。
天气接口是**真实请求过**的，不是照文档写的。

## 四、数据的可信度（重要）

`data/places.js` 里的经纬度、价格、预约规则、开放时间**都是整理值，没有逐条核实**，
每条都带了 `source` 和 `lastVerifiedAt` 字段。上线前必须做两件事：

1. 用[腾讯位置服务坐标拾取器](https://lbs.qq.com/tool/getpoint/)逐个核对经纬度（gcj02，和小程序一致）；
2. 核实收费、预约、闭馆日，并更新 `lastVerifiedAt`。

PRD 里强调过：开放时间、停车、收费、预约规则都会变，`last_verified_at` 是这类产品的生命线。

## 五、常见改动怎么做

**加一个地点**：在 `data/places.js` 数组里复制一条改，`id` 不要重复。

**加一个分类**：
1. 在 `data/categories.js` 的 `CATEGORIES` 里加一项（key / label / emoji / color）；
2. 在 `tools/gen_assets.py` 的 `CATS` 里加同样的 key，跑一次
   `python tools/gen_assets.py` 生成 `images/markers/<key>.png`。

**加一个专题**：在 `data/topics.js` 里加一项，`filters` 用 `emptyFilters()` 里的字段。
发现页和专题页会自动带上它，不需要写页面。

**换主题色**：改 `app.wxss` 里 `page { --brand: ... }` 这组变量。
Marker 和 TabBar 图标的颜色写在 `tools/gen_assets.py` 顶部，改完要重新跑一次生成。

## 六、配色与图标

**配色（2026 自然暖白）**，定义在 `app.wxss` 的 `page { --xxx }` 里：

| 变量 | 色值 | 用在哪 |
|---|---|---|
| `--brand` | `#4B7A5A` 森林绿 | 主按钮、选中态、Marker 主色 |
| `--brand-dark` | `#3A6248` | 强调文字、TabBar 选中 |
| `--brand-soft` | `#E6EDE6` | 次要按钮底 |
| `--bg` | `#F3F1EC` 暖白 | 页面底色 |
| `--clay` | `#B5714C` 陶土 | 点缀色 / 文化类分类 |
| `--blue` | `#3F7F8C` 雾蓝 | 玩水、海边分类 |
| `--plum` | `#7E6A92` 紫灰 | 游乐运动分类 |
| `--gold` | `#D9A441` 柔金 | 星级 |
| `--text` `--sub` `--faint` `--line` | 暖中性灰 | 文字与分割线 |

思路是把原来偏鲜艳的草绿换成低饱和森林绿，底色从冷灰白换成暖白，
分类色统一压低饱和度 —— 更接近户外自然感，也不容易看腻。不用母婴粉。

**图标**由 `tools/gen_assets.py` 生成（需要 Python + Pillow）：

- **地图 Marker**：白底 + 分类色描边的水滴针，中间是分类 emoji；颜色只有四组。
- **TabBar**：自己画的线性图标，未选中=线框灰、选中=实心绿。
  童年地图那个原本试的是脚印，缩到 27pt 会糊成一团，换成了小旗（插旗=「我们来过」）。

改完颜色或加了分类，跑一次：

```
python tools/gen_assets.py
```

## 八、需要真机验证的地方

模拟器和 Node 里能验的都验过了，这几处**必须真机确认**：

- **足迹卡片出图**：canvas 2d 的绘制逻辑跑过（坐标不溢出、无 undefined），
  但字体渲染和 emoji 的实际效果得看真机；
- **相册权限**：第一次保存会弹授权，拒绝后走「去设置」引导；
- **模糊定位**：`wx.getFuzzyLocation` 不用申请，但真机第一次进仍会弹授权框，
  拒绝后要确认走的是深圳市中心兜底而不是白屏；
- **本地文件空间**：打卡照片存在本机，小程序总共只有 10MB，
  照片多了要考虑压缩或改存云存储；
- **天气的域名白名单**（Phase 5，最容易漏）：`https://api.open-meteo.com`
  必须加进 mp 后台的 request 合法域名。开发者工具勾了「不校验合法域名」照样能跑，
  **只有真机会失败**。真机上顶栏显示「域名未在 mp 后台配置」就是这个原因；
- **摇一摇**：`wx.startAccelerometer` 在模拟器里摇不出来，只能真机试。
  阈值是三轴合力 2.2g（`pages/today/today.js` 的 `SHAKE_THRESHOLD`），
  觉得太灵敏或太迟钝就改这个数。拿不到重力感应的设备会自动降级成只能点按钮。

按 PRD 的要求，**每个 Phase 完成后先测试再进入下一个**。
