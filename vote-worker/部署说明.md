# 投票功能部署说明

投票的数据存在 Cloudflare 上（Worker + KV），**和你家里这台电脑无关**——
电脑关机、隧道断了，大家照样能投票、能看到结果。网页本身还是走你原来的隧道。

整个部署只做一次，之后改网页内容不用再动这里。

## 一、部署（约 5 分钟）

在**这个文件夹**（`vote-worker`）里打开 PowerShell，依次执行：

### 1. 登录 Cloudflare

```powershell
npx wrangler login
```

会自动打开浏览器让你点「Allow」授权，点完回到命令行就行。

### 2. 创建 KV 存储空间

```powershell
npx wrangler kv namespace create VOTES
```

输出里会有一行类似：

```
id = "8f3c1a2b4d5e6f7890abcdef12345678"
```

把这串 id **复制下来**，填到 `wrangler.toml` 里 `id = "在这里填 KV namespace 的 id"` 那一行。

### 3. 部署

```powershell
npx wrangler deploy
```

看到 `Uploaded szkids-vote` 和 `szkids.dpdns.org/api/*` 就成功了。

### 4. 验证

浏览器打开 <https://szkids.dpdns.org/api/votes>，应该看到：

```json
{"ok":true,"total":0,"list":[]}
```

然后打开 <https://szkids.dpdns.org>，每个活动卡片底部就有投票按钮了。

## 二、日常使用

- **看票**：网页上直接看，或访问 `https://szkids.dpdns.org/api/votes`
- **清空重来**（比如下个月换一批活动）：

  ```powershell
  npx wrangler kv key list --binding VOTES --remote
  ```

  拿到 key 列表后逐个删：

  ```powershell
  npx wrangler kv key delete "v:xxxxx" --binding VOTES --remote
  ```

  嫌麻烦的话，直接在 `wrangler.toml` 里换一个新的 KV namespace，旧票就都看不见了。

- **关掉投票**：改 `index.html` 里 `PAGE.vote: true` → `false`，投票区就整块消失（数据还在）。

## 三、几件需要知道的事

**票数不是马上全球同步的。** Cloudflare KV 的 list 结果有缓存，实测新票要 **30~60 秒**
别人才看得到（部署当天测了两次：31 秒、约 20 秒）。
所以页面做了「乐观显示」：你自己投的票立刻就出现，别人的票过一会儿刷新一下就有了。
如果哪天觉得这个延迟不能接受，得把存储从 KV 换成 Durable Object（强一致，但代码要重写）。

**防刷是弱防护。** 页面公开、没有登录，靠的是浏览器本地标识 + 同一 IP 每小时最多 12 次写入 +
总人数上限 300 人。熟人群够用，但挡不住真心想刷票的人。

**昵称是公开的。** 任何拿到链接的人都能看到所有投票人的昵称。介意的话，把
`index.html` 里 `renderVotes()` 中的 `.vote-names` 那一行改成不显示名字即可。

**免费额度。** Worker 每天 10 万次请求、KV 每天 10 万次读 / 1000 次写，
几十个人投票远远用不完。

## 四、改动了哪些文件

| 文件 | 作用 |
|---|---|
| `vote-worker/src/index.js` | 后端接口：`/api/votes` 查票、`/api/vote` 投票、`/api/unvote` 取消 |
| `vote-worker/wrangler.toml` | 部署配置（路由 + KV 绑定） |
| `index.html` | 每个活动加了 `voteId`；`PAGE.vote` 开关；投票 UI 和逻辑（文件末尾第 ④ 段） |

存储结构：一个投票人一个 KV key（`v:<投票人ID>`），选项和昵称放在 metadata 里。
不用「票数计数器」是因为两个人同时投票会互相覆盖导致丢票。
